# 简化双机工作流：人工优先，主力自主推进，发布独立验证

版本：1.5 · 2026-09-28。后续优先按本页启动任务；详细暂停/团队协议作为异常情况参考。本页更新规则，不恢复当前暂停、不启动自动化或实验。

## 1. 只保留两条工作线

主力负责“做什么、为什么、怎么改”；发布负责“怎样验证、实际怎样、还缺什么证据”。主力自动不是传声筒，可在有效任务范围内主动分析、提出下一步方案；夜间获得授权和写入权后，继续改代码、自测、交付候选与实验单。

| 工作 | 主力机 | 发布机 |
| --- | --- | --- |
| 问题分析与方案 | 主责；维护假设和最小区分实验，解释方案取舍 | 提供现场约束、反证和可测性建议 |
| 运行代码、架构和正式测试改动 | 实现、补回归、自测、统一整合提交 | 不自行混入生产补丁；问题与独立补丁交回主力 |
| 部署与现场验证 | 给出候选、预期和边界，不代替现场执行 | 按本地 skill 使用既有容器，唯一负责部署/执行/清理 |
| 补充验证与测试 | 规定验收目标，不必列举每个测试用例 | 在批准的测试范围与预算内补边界、回归、短复现、日志关联及测试脚本 |
| 结果和下一轮 | 根据证据修正方案，产出新候选或下一实验 | 报告通过/失败/不完整及首错、命令、版本、日志 |

发布机补测前写清验证问题与参数差异，结果单独编号。可以改变已批准矩阵内的测试参数，不能悄悄改评分口径、服务算法或把诊断结果当正式精度结果。可复用的测试脚本/用例由主力审阅后整合，不要求发布机只等逐条指令。

## 2. 白天与夜间：同一流程，不是两套团队

- 白天人工优先：用户决定方向；主力自动可以读取新证据、给 DESIGN 建议，但不能与人工同时写同一目录或擅自发布执行单。收到人工改动指令先确认接管，旧自动动作在安全点停下。
- 夜间有界自主：用户一次批准当前问题、环境、允许修改/测试范围及截止/最多轮次后，主力可自行提方案、实现、自测并按授权推候选；发布可接单验证、补测并回传。范围内不必每一个步骤都等用户。
- 主力发下一轮 EXECUTE 时记录固定 SHA/环境、要区分的假设、预期、测试范围与停止条件；发布接单核对即可，不必每个小测例重复双端审批。重大范围变化才回到用户。
- 新 SHA 在登记和接单后才可部署，不是跟随 branch latest。人工后来的暂停/变更优先于夜间计划。
- 到期、预算耗尽、未知设备状态或超出授权范围时，保存结果、按预先约定保留/释放资源，并回报需要用户决定的事项。相同失败且没有新证据时不无限重试。

主力与发布每侧各一个活动执行 owner。已有人工/自动分离窗口无需重建：自动窗口若要直接执行，先从人工侧接过同一工作目录的写入权；或者由它唤醒既有固定执行会话。两种方式选择一种并记录，不能同时推进。单纯监听/转发组件仍不具备代码写入或设备操作权。

不需要为了白天/夜间切换新建聊天、PR、工作树或 agent team。团队可按此前明确授权按需使用；简单任务由负责人直接完成。

## 3. 现在先固定环境，避免每轮从头准备

主力保留一个已核实的项目目录与开发环境，发布保留其本地 skill 和指定容器环境。不同任务的日志、测试输出和 run_id 分开；同一功能的修复循环沿用已有实现分支，不为每次实验换工作区。

首次确认时记录一张简短环境卡：env_id、验证状态、代码基线与配套版本、主力工作目录/解释器、发布镜像 digest、实际 CANN/OPP/wheel、模型/拓扑、skill 路径与版本、上次核对证据。

后续主力引用 env_id，仅核对变化；发布每次运行仍快速确认资源归属、设备/端口可用、无旧请求、实际源码/导入路径和环境卡是否一致。不重复完整安装、全量环境审查或拉起新容器。

以下变化使相关核对失效：换镜像/容器软件栈、依赖/OPP/驱动/固件改变、换模型/拓扑、改 editable import 路径、出现环境故障。只重查受影响部分，不机械重做全部流程。任务、分支或候选 SHA 变化仍需要相应回归，不因复用环境而跳过。

环境卡分“待核实/已验证/存在阻碍”。当前 d7 启动存在 HCCL/AICPU 问题，不能因用户希望固定环境就标成健康；以后按新授权排除阻碍并留下证据后，才把它作为可复用验证环境。主力固定开发环境也不代表能本地运行 NPU 测试。

新建容器不等于必须重装一切；是否能复用由镜像与实际包/挂载一致性决定。服务是否重启取决于代码加载、配置和状态，不要求每个短测都关服务，也不允许运行中覆盖其源码或包。

## 4. 日常只用一张轻量任务卡

用户只需说明目标、环境和自动范围，以下编号由两侧负责人填写：

```text
任务/主控制入口：
目标与完成标准：
env_id / 主力目录 / 发布容器及 skill：
主力活动 owner / 发布活动 owner：
基线、配套版本与当前完整候选 SHA：
白天/夜间范围：可改什么、可推送吗、发布可补哪些测试：
截止时间 / 最多轮次 / 停止与资源保留释放规则：
最新实验单 / run_id / 结果证据 / 下一步：
```

主力维护当前计划与候选，发布维护实际环境和结果。每轮沿用同一主入口，只追加有变化的字段和证据，避免把几百行旧实验反复复制到自动提示中。

任务卡背后的 epoch/command_id 去重和暂停回执仍保留，由负责人管理，不要求用户每句话填写全部控制字段。完成长暂停或人工接管后，第一次恢复仍需双方确认实际状态与新计划。

## 5. 什么时候要新起东西

| 情况 | 最小操作 |
| --- | --- |
| 同一问题继续、白天转夜间、短暂停后恢复 | 沿用两边会话/工作目录/环境，更新任务卡与授权；必要时新 run_id |
| 同项目串行切换另一问题 | 前一任务先收尾，换 task_id 和任务卡；独立代码改动通常用自己的分支/PR，开发环境可复用 |
| 新功能与旧功能要同时做，或基线互不兼容 | 才考虑新聊天及独立工作树/环境；不要让两个任务写同一 checkout |
| 发布镜像/依赖不兼容，或旧容器状态不可信 | 由发布机按 skill 与授权处理容器/环境，更新环境卡；主力无需跟着无意义换目录 |
| 仅聊天上下文难管理，需要新会话 | 携带任务卡、协议固定提交、证据索引和 owner 交接；先确认旧执行已停，不必默认重建容器 |

默认方案：两边现有会话 + 主力固定工作目录 + 发布现有容器/本地 skill + 每任务一张卡。无需新增常驻“总控任务”或为每个测试建 PR。

## 6. 以后怎么启动：可直接复制

### 发给主力机

> 按协作 v1.5 的简化双机流程处理任务……。沿用已核实的主力目录和 env_id……，不随意换环境。主力负责主动提方案、代码与正式回归修改、自测和候选交付；发布机负责现场验证并在……范围补测。先整理轻量任务卡，确认两侧活动 owner。现在先白天人工优先；未收到夜间授权前可以给建议，不启动无人值守执行。遇环境变化只补受影响的核对。

### 发给发布机

> 本侧为发布机，沿用容器……、env_id……和本地 skill……。按主入口……的当前任务卡与获准实验单接单，不追随最新 head。负责部署验证，可在……测试范围和预算内补边界/回归/短复现及脚本；算法、生产代码及正式方案改动交回主力。每轮返回实际 SHA、环境差异、命令、结果和证据。只读取文档不构成启动，先回报准备情况及阻碍，等本任务明确授权。

### 晚上挂起前，一次发给双方

> 今晚允许任务……在 env_id……上按 v1.5 自主协作至……，最多……轮。主力可围绕……主动设计实验、修改……、自测并【允许/不允许】推送本任务候选；发布机可按主力的明确实验单验证并补……范围测试。采用同一主入口交接，允许在该范围内发布/读取实验单和结果；直接跨聊天转交权限与可达性先核实。禁止换基线/升级环境/扩大模型或负载上限/合并发布。每轮固定 SHA；无新增证据的重复失败停下，资源保留/释放按……。主力与发布确认 owner 和准备状态后，从……开始；人工后续指令优先。

以上是未来启动模板，不是对当前暂停任务的恢复。字段未填时不自行编造额度、截止或推送授权；用户可以在原有授权范围内补充说明。

## 7. 主力自主与发布补测的长期提示模板

主力：在当前有效任务和环境卡内，主动消化发布结果、维护假设、提出能区分原因的下一方案。只有当前模式授权执行且本会话持有主力写入权时，才修改代码、自测并按允许范围交付固定 SHA/实验单；否则记录 DESIGN 建议。对范围内的夜间闭环主动推进，不只等待人工逐条下令。暂停或授权到期停止新动作，不把旧提示里的历史实验当新授权。没有实际跨机投递/接单证据时报告未送达，不声称发布机已启动。

发布：按自己的本地 skill 在固定环境接收获准实验，判断需要哪些补充验证；在矩阵和预算内自行补测并注明参数差异。不改生产算法或评分标准，不推主力共享分支。已授权的同服务检查可连续做；换代码/包/参数或状态不可信时按计划重启。首错、失败与未知及时回传，正常结果也给证据；不因新 SHA 存在就自动部署，须有对应有效实验单。

本次只发布上述规范，未更新真实自动化提示或恢复其状态。启用时更新已有实例而不新建重复实例，并确认同一协议、owner、夜间范围和实际消息通道；单边配置不能证明另一边已经同步。

相关工作的连续推进适合保留同一会话；真正独立并行的工作再隔离，并明确结果、限制和验收标准。这与[官方长期任务指导](https://learn.chatgpt.com/docs/long-running-work)一致；本文不要求启用额外 Goal 或调度产品才能执行本工作流。
