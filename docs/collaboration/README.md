## v1.5 调整：主力自主、发布补测、固定环境

- 主力自动不仅转交：可以主动分析和提出 DESIGN；夜间接权并获授权后自行设计实验、实现、自测和交付候选。
- 发布在批准矩阵与预算内自主补测，正式代码和可复用测试由主力整合；不逐用例等待主力下令。
- 主力固定开发目录/环境，发布沿用容器与本地 skill；首次环境卡确认后按变化增量核对，保留每次必要资源检查。
- 不要求新建聊天、团队或调度实例；日常只用轻量任务卡，详细控制字段由负责人维护。

## 继承自 v1.4 的窗口与团队边界

- 延续 v1.3 的暂停/交权/恢复机制，增加两机四入口职责；每机固定一个活动执行者；纯监听不成为第二个执行者，主力自动可通过明确交权接任。
- 区分 MANUAL、OBSERVE、AUTO_BOUNDED，自动推进必须有明确动作范围、时限和次数预算。
- 两侧团队按需启动，各自负责人汇总；子代理默认不推共享分支、不跨机派活、不并发操作共享 NPU。
- 恢复前审阅已有自动化提示和目标会话；协议文件不会自动替换旧提示或唤醒另一账号。

## 继承自 v1.3 的交接约束

- 暂停不是停服务；接收回执不是安全交权；就绪不是执行。
- 增加 control_epoch、pause_id、plan_revision、command_id 和指定 owner，重复/过期命令不重放。
- 人工修改记录代码、配置、环境和证据差异，恢复前双端对同一协议提交、计划和候选确认。
- 自动监听是否恢复单独选择；不新建重复监听、不借恢复一项实验恢复全部旧任务。
- 服务复用、待命窗口、资源释放与可信状态按具体实验单约定，不无限占用或每项短测后机械重启。
- 仍是人工交接协议；没有技术锁时不声称具备强制互斥、即时跨机暂停或自动同步能力。
